# Modelo de amenazas — CoreBiz

Análisis STRIDE del sistema, con las mitigaciones implementadas y los riesgos aceptados
de forma consciente. Este documento se actualiza cuando cambia la superficie de ataque,
no cuando ocurre un incidente.

> El código de CoreBiz es **público**. Eso es deliberado: la seguridad del sistema no
> depende de que nadie lo lea. Si esconder el código fuese necesario para que el
> aislamiento entre empresas aguantase, el aislamiento no sería tal.

---

## 1. Activos que se protegen

| Activo                       | Por qué importa                                                                                                            |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| Datos de cada empresa        | Clientes, precios de compra y venta, márgenes, inventario. Que un comercio vea los precios de otro es el fin del producto. |
| Credenciales y sesiones      | Un secuestro de sesión da acceso completo al tenant.                                                                       |
| Registro de auditoría        | Si se puede editar, deja de servir para lo único que existe.                                                               |
| **Cuota de infraestructura** | El presupuesto es $0. Agotar la cuota gratuita tumba el sitio, y un enlace de CV caído es el peor fallo posible aquí.      |

## 2. Fronteras de confianza

```
  Navegador  ──┐  nada de aquí es de fiar
               │
      ╔════════▼═══════════════════════════════════════════╗
      ║ Vercel Edge — middleware, CSP, rate limit           ║
      ╚════════┬═══════════════════════════════════════════╝
               │
      ╔════════▼═══════════════════════════════════════════╗
      ║ Vercel · Función Node — Next.js                     ║
      ║   SOLO transporte. No decide nada, no toca la base. ║
      ║   Reenvía el token; nunca se lo da al navegador.    ║
      ╚════════┬═══════════════════════════════════════════╝
               │  HTTPS servidor a servidor, Bearer + hash de IP
               │  ── FRONTERA DE CONFIANZA NUEVA ──
      ╔════════▼═══════════════════════════════════════════╗
      ║ Vercel · NestJS — la API                            ║
      ║   Verifica la firma  →  resuelve el tenant          ║
      ║   Zod valida  →  caso de uso decide  →  dominio     ║
      ╚════════┬═══════════════════════════════════════════╝
               │  transacción con app.tenant_id fijado
      ╔════════▼═══════════════════════════════════════════╗
      ║ Supavisor (pooler) → PostgreSQL con RLS forzada     ║
      ╚════════════════════════════════════════════════════╝
```

## 3. Análisis STRIDE

### S — Suplantación de identidad

| Amenaza                                          | Mitigación                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Robo de sesión                                   | Cookies `httpOnly`, `Secure`, `SameSite=Lax`. El JWT nunca toca `localStorage`.                                                                                                                                                                                                                                                                                                                                                                      |
| Token falsificado                                | La API **verifica la firma criptográficamente** contra el JWKS del proyecto, con los algoritmos asimétricos **declarados explícitamente** (`ES256`/`RS256`) y nunca deducidos. Nunca se decodifica sin verificar. En `apps/web` se usa `getSession()` para SACAR el token y reenviarlo —no para decidir nada— y esa distinción está escrita en el archivo y en ADR 006, porque el siguiente lector la va a "arreglar" en una dirección o en la otra. |
| Suplantación entre los dos servicios             | La API no se fía de nada que le llegue por cabecera: el rol sale de la pertenencia leída de la base y las cabeceras de demostración solo se obedecen dentro de un tenant `is_demo` **y** siendo ya propietario, así que solo pueden quitar permisos. Los endpoints internos van tras un secreto compartido comparado en tiempo constante, y responden **404** si no está configurado.                                                                |
| **Entrar como dueño de la plantilla de la demo** | La semilla de producción crea la cuenta dueña de la plantilla con una contraseña aleatoria que nadie conoce y **sin identidad de correo**, así que no se puede iniciar sesión con ella. Antes llevaba una contraseña escrita en el repositorio público. La contraseña conocida solo existe en `supabase/seed.local.sql`, que carga la CLI local y la guía de despliegue prohíbe ejecutar en producción.                                              |
| Enumeración de correos en el login               | Un único mensaje para "no existe" y "contraseña incorrecta", en acceso y en recuperación. La recuperación responde "enviado" siempre, incluso con una dirección sin cuenta.                                                                                                                                                                                                                                                                          |
| Fuerza bruta                                     | Límite por **hash de IP**, no por correo: contar por correo permitiría dejar fuera a una persona concreta gastándole los intentos, y convertiría la respuesta en un oráculo sobre qué direcciones existen. UPSERT atómico en Postgres — un contador en memoria de proceso no limita nada en serverless.                                                                                                                                              |
| Referencia de incidencia falsa usada como gancho | La web solo pinta bajo «Referencia» lo que tiene la forma exacta que fabrica la API (`INCIDENT_ID_PATTERN`, un único patrón para los dos lados), validado al escribir la cookie y al leerla. Un texto como «llame a este número y facilite su contraseña» no llega a la pantalla con el aspecto oficial de la aplicación.                                                                                                                            |

### T — Manipulación de datos

| Amenaza                                                     | Mitigación                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ----------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Salto de tenant** manipulando el slug o un id en la URL   | RLS + comprobación de pertenencia + filtrado explícito en el repositorio. Cuatro capas, ver ADR 005.                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Mover una fila propia al tenant de otro                     | `WITH CHECK` en las políticas de `UPDATE`. Solo con `USING`, esa escritura pasaría.                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Mass assignment por campos colados en el cuerpo             | Los comandos extraen **solo los campos declarados**; lo que no está en la lista no llega al dominio.                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Edición del registro de auditoría                           | `UPDATE` y `DELETE` **revocados por GRANT**, no solo por política: una política se sustituye con un `create policy` posterior, un privilegio revocado no.                                                                                                                                                                                                                                                                                                                                                                                 |
| Borrado de documentos                                       | Política de `DELETE` en `false`. Los documentos se anulan, nunca se borran.                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| CSRF                                                        | Next valida el `Origin` de las Server Actions. Cookies `SameSite=Lax`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| **Sobreventa por escritura concurrente del saldo**          | El saldo de inventario no se incrementa en la base: lo calcula el agregado y se escribe absoluto. Con `READ COMMITTED` dos ventas simultáneas leían el mismo saldo y la segunda pisaba a la primera — ocho unidades salían del almacén y el libro decía cuatro, con dos movimientos apuntando el mismo saldo posterior. El repositorio toma ahora `select … for update` **antes** de leer, y siempre en el mismo orden de id para no cambiar una condición de carrera por un bloqueo mutuo. Hay test de integración con control negativo. |
| **Envenenar la plantilla que se clona para cada visitante** | Trigger `trg_guard_demo_template` en `tenants` y en toda tabla con `tenant_id`: los roles de usuario no pueden escribir filas de la plantilla mientras `demo_template_locked` esté activo, **y lo está por defecto**. Las funciones de clonado y aprovisionamiento corren como el dueño del esquema y siguen funcionando. Un test compara la lista de tablas con disparador contra el catálogo.                                                                                                                                           |

### R — Repudio

| Amenaza                                                | Mitigación                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| "Yo no emití esa nota"                                 | Registro de auditoría inmutable con actor, acción, entidad y marca temporal, escrito **en la misma transacción** que el cambio. Si la auditoría falla, el cambio se deshace.                                                                                                                                                                                                                                                                                         |
| Inventario que no cuadra sin explicación               | El stock es el saldo de movimientos registrados, no un campo que se fija. Los ajustes exigen motivo.                                                                                                                                                                                                                                                                                                                                                                 |
| **Auditoría que no dice quién**                        | Cada fila guarda `actor_id` y además `actor_email` **del token ya verificado**, más `ip_hash` y `user_agent`. Las tres columnas existían desde la primera migración y nada las escribía: el filtro por correo no podía coincidir y la columna «actor» del CSV salía vacía. `ip_hash` y `user_agent` los reenvía la capa web por cabecera, así que quien llame a la API directamente puede inventarlos: el dato firme de una fila es `actor_id`, luego `actor_email`. |
| **Llevarse el registro de auditoría sin dejar rastro** | Exportar el CSV escribe una fila `audit.exported` con el número de filas y los filtros, **antes** de devolver el archivo, por un caso de uso que vuelve a comprobar `audit:export`. Las lecturas en pantalla siguen sin registrarse: ver «Pendiente».                                                                                                                                                                                                                |

### I — Divulgación de información

| Amenaza                                                      | Mitigación                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Variable de tenant pegada a una conexión del pooler**      | `set_config(..., true)` — local a la transacción. Con `false`, la variable sobreviviría a la petición y Supavisor reutilizaría esa conexión para **otro tenant**. Es la fuga más difícil de detectar del sistema, porque solo aparece bajo concurrencia. Hay un test que la cubre.                                                                                                                                                                            |
| **Fuga de la clave `service_role`**                          | **No existe en el despliegue.** Es la única mitigación que no puede fallar: lo que la clave permitiría —crear una empresa, aceptar una invitación, provisionar una demostración— entra por funciones `SECURITY DEFINER` acotadas y revocadas de `public`. Una llave maestra guardada por si acaso acaba filtrándose; la que no se guarda, no.                                                                                                                 |
| El propietario de la tabla salta sus políticas               | `FORCE ROW LEVEL SECURITY`, no solo `ENABLE`.                                                                                                                                                                                                                                                                                                                                                                                                                 |
| **Escalada vía `SECURITY DEFINER`**                          | Todas las funciones llevan `set search_path = ''` y nombres completamente cualificados. Sin eso, quien pueda crear objetos en un esquema del `search_path` secuestra el nombre de una tabla.                                                                                                                                                                                                                                                                  |
| Datos de un tenant servidos desde caché compartida           | Toda pantalla con datos lee cookies y pide a la API con `cache: 'no-store'`, así que Next la trata como dinámica; `staleTimes.dynamic` está en 0. Verificado por un test E2E que comprueba la cabecera `Cache-Control`. **No se declara `force-dynamic` en el segmento**: el efecto es el mismo y la garantía es más débil, porque depende de que nadie deje de leer cookies en una pantalla.                                                                 |
| IDOR sobre documentos                                        | Identificadores UUID v7 y toda lectura acotada por tenant. Un id ajeno responde 404, no 403: un 403 confirmaría que el recurso existe.                                                                                                                                                                                                                                                                                                                        |
| Archivos accesibles sin permiso                              | **No aplica: el sistema no almacena archivos.** No hay adjuntos ni Supabase Storage. Se deja la fila para que la ausencia sea deliberada y no un olvido.                                                                                                                                                                                                                                                                                                      |
| Reconocimiento del framework                                 | `poweredByHeader: false`. No evita un ataque, pero no hay razón para regalar la versión.                                                                                                                                                                                                                                                                                                                                                                      |
| **Script inyectado que se ejecuta** (XSS)                    | CSP con **nonce distinto por petición** y `strict-dynamic`, que descarta las listas de dominios y confía solo en el nonce. Como toda la autenticación es de servidor, el token de sesión vive en una cookie `httpOnly` y un XSS no llega a él.                                                                                                                                                                                                                |
| Enmarcado de la aplicación en un sitio ajeno                 | `frame-ancestors 'none'` y `X-Frame-Options: DENY`.                                                                                                                                                                                                                                                                                                                                                                                                           |
| Reescritura del destino de los formularios                   | `base-uri 'none'` y `form-action 'self'`. Sin la primera, un `<base>` inyectado redirige **toda** URL relativa de la página, envíos con credenciales incluidos.                                                                                                                                                                                                                                                                                               |
| **Redirector abierto en los parámetros `next`**              | `/waking-up` y `/auth/callback` decidían si el destino era interno mirando la cadena (`empieza por "/" y no por "//"`), y `/\otro-sitio` se colaba: el navegador trata la barra invertida como barra y lo resuelve a otro origen. Ahora lo decide `safeInternalPath`, que RESUELVE el destino contra un origen de control y compara: el mismo algoritmo que usará el navegador, en vez de una imitación. Cubre `//host`, `/\host`, absolutas y `javascript:`. |
| **Credencial en el log por la cadena de consulta**           | El filtro global registra la ruta **sin** query string. `GET /v1/invitations/preview?token=` lleva una credencial portadora, y `?search=` y `?actorEmail=` llevan nombres de clientes y correos: la auditoría guarda solo el hash del token, y el log no puede ser la puerta de atrás. La empresa se anota como _pedida_ junto al usuario verificado, para que una cabecera falsificada no atribuya una incidencia a otra empresa.                            |
| **Hashes de IP reversibles por una sal publicada**           | `REQUEST_HASH_SECRET` es obligatorio en producción (`requiredSecret`): si falta, la web responde con error en lugar de caer a la sal de desarrollo que está en el repositorio.                                                                                                                                                                                                                                                                                |
| Explicación del error ajeno en un puesto compartido          | El panel de ayuda recuerda el último error en una cookie del **navegador**, no de la persona. Se borra cuando una escritura sale bien, al cerrar sesión y al cambiar de empresa, y caduca a los cinco minutos.                                                                                                                                                                                                                                                |
| **Atributos de la cookie de sesión pisados por la librería** | Los dos sitios que escriben cookies de Supabase aplican `httpOnly`, `secure` y `sameSite` **después** de las opciones de la librería. En `auth/supabase.ts` estaba al revés, así que una versión futura de `@supabase/ssr` podía rebajarlos sin que nada lo indicara. La librería sigue decidiendo cuánto dura la cookie, no quién puede leerla.                                                                                                              |
| Confirmar existencia por el texto                            | La regla del 404 vale también para las palabras: `NotFound` dice «no encontramos», nunca «ya no está», que afirmaría que estuvo. Las fichas `*NotFound` ofrecen siempre la explicación inocente —archivado, enlace antiguo— sin distinguir «no existe» de «no es tuyo».                                                                                                                                                                                       |

### D — Denegación de servicio

| Amenaza                                               | Mitigación                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Agotar la cuota gratuita** (el riesgo más realista) | Circuit breaker sobre **tamaño de base de datos y sandboxes vivos** (umbrales 0,70 y 0,85 sobre 500 MB). Al superarlos, **la demostración** degrada a solo lectura en vez de rechazar al visitante; falla cerrado si no puede leer el tamaño. **Protege el aprovisionamiento de demos, no la aplicación entera**, y la API no tiene limitador propio: ver «Pendiente».                                                                                                                                                                                                    |
| Granja de sandboxes de demostración                   | Provisión solo por `POST` con verificación de `Origin` — un `GET` nunca crea nada. Cookie que reutiliza el sandbox existente, tope global de sandboxes vivos y el **mismo secreto compartido** que los endpoints internos (el limitador cuenta por un `ipHash` que viaja en el cuerpo, así que con la ruta abierta se evadía llamando a la API directamente). Al agotarse la capacidad, los puestos de solo lectura tienen **techo por hora** (`DEMO_MAX_READONLY_PER_HOUR`): antes cada petición creaba cuenta, identidad, membresía y sesión sin que nada lo rechazara. |
| Escrituras masivas                                    | **Límite por usuario verificado** en toda escritura de la API (`WriteThrottleGuard`, `API_WRITES_PER_HOUR`, 600 por hora por defecto), con el contador en Postgres para que valga entre instancias. Frena un script que llena la base; no sustituye a las cuotas, que el producto decidió no tener. Ver «Riesgos aceptados».                                                                                                                                                                                                                                              |
| Consulta que abre N conexiones                        | `GET /v1/usage` solo admite recursos conocidos y como mucho tantos como existen: cada recurso era una consulta en paralelo, y una lista de miles agotaba las diez conexiones del pool para todas las empresas.                                                                                                                                                                                                                                                                                                                                                            |
| Limitadores de acceso apagados por mala configuración | Si `INTERNAL_API_SECRET` falta o no coincide entre los dos proyectos de Vercel, los intentos de acceso, alta y recuperación se **niegan** en producción. Antes se admitían en silencio, con solo un aviso en el log. Si la API solo está dormida se sigue admitiendo, a propósito.                                                                                                                                                                                                                                                                                        |
| Consultas caras                                       | Índices que empiezan siempre por `tenant_id`, y paginación por keyset **en clientes y proveedores**. Productos, notas de entrega y recepciones sirven un `LIMIT` fijo. Sin `OFFSET` en ninguno.                                                                                                                                                                                                                                                                                                                                                                           |
| **`/api/health` como amplificador**                   | Es pública y espera hasta 45 s a que la API despierte: cada petición anónima retenía una función de Vercel ese tiempo. Ahora la comprobación se reutiliza durante 10 s y las peticiones simultáneas comparten **una** sola en vuelo; la respuesta sigue siendo `no-store`. El límite es por instancia, no global.                                                                                                                                                                                                                                                         |
| Identificador mal formado que acaba en 500            | Sobre Postgres un id que no es uuid reventaba en la base (`22P02`) y salía como error del servidor; en memoria daba 404, así que la suite por defecto no lo veía. El adaptador descarta lo que no puede ser clave (`prisma/record-id.ts`) y responde lo mismo que para un id inventado.                                                                                                                                                                                                                                                                                   |
| Pantalla que se cae por un 403 de rol                 | El menú y las pestañas solo ofrecen lo que el rol puede abrir (`auth/module-access.ts`), cada pantalla comprueba `can()` **antes** de leer y pinta un aviso en vez de dejar que el 403 suba como excepción, y hay `app/error.tsx` y `app/not-found.tsx` propios, en el idioma de la aplicación y sin estilos en línea que viole la CSP. No cambia ningún límite: la autorización sigue en el caso de uso.                                                                                                                                                                 |
| **Cookie manipulada que tumba el marco**              | El panel de ayuda se monta en las 21 pantallas con sesión y lee una cookie que quien usa el navegador puede escribir. `parseLastFailure` (`packages/contracts/src/support.ts`) nunca lanza, descarta cualquier `kind` que no sea una clave y cualquier referencia sin la forma `INC-XXXXXXXX`, y las claves heredadas del prototipo no cuentan (`Object.hasOwn`). Antes, un objeto en la cookie reventaba el render de todas las pantallas a la vez durante cinco minutos.                                                                                                |

### E — Elevación de privilegios

| Amenaza                                             | Mitigación                                                                                                                                                                                                                                                                                                                                                                                                         |
| --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Rol elevado por manipulación del cliente            | El rol se lee de la pertenencia en base de datos, nunca del cliente. La autorización se comprueba en el **caso de uso**: ocultar un botón no es una medida de seguridad, porque la Server Action se puede invocar directamente.                                                                                                                                                                                    |
| Un administrador se auto-asciende a propietario     | Políticas sobre `memberships` + trigger `enforce_last_owner`.                                                                                                                                                                                                                                                                                                                                                      |
| Un administrador degrada o expulsa a un propietario | El caso de uso lo rechaza (`OnlyOwnerManagesOwners`) y las políticas de `memberships` lo repiten: una fila de propietario solo la cambia o borra otro propietario, y nadie que no lo sea escribe `role = 'owner'`. El trigger del último propietario solo protegía al último.                                                                                                                                      |
| Un administrador reescribe qué es la empresa        | Privilegios por columna en `tenants`: el rol de usuario solo puede actualizar los campos de ajustes (nombre, impuesto, moneda, tasa). `plan_code`, `is_demo`, `status` y `expires_at` solo cambian por funciones de plataforma.                                                                                                                                                                                    |
| **Cambiar la contraseña con una sesión robada**     | La pantalla de nueva contraseña exige una marca firmada (HMAC sobre el usuario y la caducidad) que solo pone `/auth/callback` al canjear un enlace de recuperación de **ese** usuario. Antes bastaba cualquier sesión, y una cookie robada se convertía en toma permanente de la cuenta.                                                                                                                           |
| Módulos de pago accesibles sin plan                 | En las ESCRITURAS lo decide el caso de uso. En las LECTURAS no hay caso de uso por el que pasar —son consultas planas— así que lo decide un guard de la API: `FeatureGuard`. Hasta que existió, la migración dejó `GET /v1/reports/sales-summary` abierto al plan gratuito. No era una fuga de datos —RLS seguía confinando cada petición a la empresa propia— pero sí una barrera de monetización que se saltaba. |

## 4. Riesgos aceptados

Decisiones conscientes, no descuidos:

| Riesgo                                        | Por qué se acepta                                                                                                                                                                                                                                                                                                                     |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Sin autenticación de doble factor**         | Fuera del alcance de un proyecto de portafolio. Supabase Auth lo soporta; añadirlo sería configuración, no rediseño.                                                                                                                                                                                                                  |
| **Rate limit de ventana fija**, no deslizante | Permite un pico al cambiar de ventana. A esta escala es irrelevante y evita una dependencia externa.                                                                                                                                                                                                                                  |
| **La demostración se sirve sin sesión**       | Es el motivo de que el proyecto tenga un enlace visitable. Está acotado: solo se sirve un tenant cuya fila está marcada `is_demo`, así que apuntar la constante a una empresa real **no la expone** — redirige a la pantalla de acceso. Se cierra entero con `DEMO_ENABLED=false`.                                                    |
| **Sin cifrado a nivel de campo**              | El cifrado en reposo de Supabase cubre el modelo de amenazas de un ERP de comercio pequeño.                                                                                                                                                                                                                                           |
| **Sin `Clear-Site-Data` al cerrar sesión**    | Cerrar sesión borra en el servidor las cookies de sesión, de empresa y del último error, y ninguna credencial vive en el almacenamiento del navegador (el token nunca llega a JavaScript). La cabecera añadiría poco, y una Server Action no puede fijar cabeceras de respuesta: exigiría convertir la salida en un route handler.    |
| **CSP sin `report-to`**                       | Recoger informes exige un endpoint público que acepte `POST` anónimos, que sería una superficie de escritura nueva y otro amplificador de cuota. Las violaciones de CSP las vigila el test E2E que navega la aplicación.                                                                                                              |
| **Sin cuotas por empresa**                    | El producto decidió no poner topes (hay tests que lo afirman). Contra el llenado de la base queda el límite de escrituras por usuario y el circuit breaker de la demostración. Un atacante con muchas cuentas puede seguir creciendo despacio; mitigarlo del todo exige cuotas o desactivar el alta abierta (`SIGNUP_ENABLED=false`). |
| **Sin recuperación a un punto en el tiempo**  | El plan gratuito no la ofrece. Mitigado porque el entorno de demostración es reconstruible desde el seed versionado.                                                                                                                                                                                                                  |

## 5. Pendiente — lo que este documento NO puede afirmar todavía

Esta sección existe porque un modelo de amenazas que afirma de más es peor que uno corto:
quien encuentre una mitigación inexistente deja de creerse las que sí están. Lo de aquí
abajo son huecos conocidos, no descuidos.

| Hueco                                                         | Estado real                                                                                                                                                                                                             | Por qué importa                                                                                                                                                                                                                                                                                                                                                                                                               |
| ------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Las lecturas de la API no tienen límite**                   | Las escrituras sí (por usuario y hora). Con un token válido se puede martillear `GET /v1/products` sin freno.                                                                                                           | RLS confina cada petición a su empresa, así que **no es fuga**; consume cuota de cómputo, no de almacenamiento.                                                                                                                                                                                                                                                                                                               |
| **Sin observabilidad**                                        | Sin Sentry ni logs estructurados; los errores van a los registros de funciones de Vercel. Lo único que hay es el identificador de incidencia de los 500 (`INC-XXXXXXXX`), en el log y en la pantalla de quien lo sufre. | Un error inesperado en producción **es invisible** hasta que alguien lo reporta: la referencia sirve para encontrarlo cuando avisan, no para enterarse antes.                                                                                                                                                                                                                                                                 |
| **Sin interruptor de solo lectura**                           | `system_flags` solo la lee el aprovisionador de demos.                                                                                                                                                                  | El paso 2 del procedimiento de incidentes no funciona hasta que se implemente.                                                                                                                                                                                                                                                                                                                                                |
| **Sin cuotas de escritura**                                   | Se retiraron al abrir el producto; la maquinaria del dominio sigue intacta.                                                                                                                                             | Es la mitigación que falta contra escrituras masivas.                                                                                                                                                                                                                                                                                                                                                                         |

## 6. Qué hacer si algo pasa

1. **Rotar claves** — `CRON_SECRET` en Vercel, `REQUEST_HASH_SECRET` en Vercel, `INTERNAL_API_SECRET` **en las dos a la vez** (es el único compartido), y la contraseña de base de datos desde el panel de Supabase. No hay `service_role key` que rotar: este despliegue no usa ninguna.
2. **Cortar escritura** — hoy no hay interruptor. La tabla `system_flags` existe y **solo la lee el aprovisionador de demos**, así que ponerla en `readonly` no detiene las escrituras del producto. Lo que sí corta de inmediato es revocar los permisos de escritura del rol `authenticated` en Postgres. Ver «Pendiente».
3. **Cerrar la demo** — `DEMO_ENABLED=false` detiene la provisión de sandboxes sin tocar el resto.
4. **Revisar el rastro** — `audit_log` filtrado por tenant y ventana temporal.
5. **Restaurar** — copias diarias con siete días de retención en el plan gratuito. **No hay recuperación a un punto exacto en el tiempo**: la pérdida máxima es de 24 horas.
